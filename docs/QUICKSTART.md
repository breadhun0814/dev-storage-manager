# 개발 저장공간 관리자 0.15.0 시험 버전

폴더 검색은 입력 후 200ms 뒤 적용하며 검색/정렬 계산 중에는 이전 목록이 잠시 보일 수 있다. 상태 문구가 완료된 뒤 행을 선택해 전체 경로를 확인한다. 검색어나 정렬 변경은 이전 계산을 취소하며 분석 데이터/실제 파일/정리 계획은 바꾸지 않는다. 숫자 정렬은 확인된 바이트/파일 수 기준이므로 미확인 범위도 함께 확인한다.

## 용량의 미확인 표시

**폴더별 용량 → 분석 범위**에서 읽기 실패/일부 제외/취소를 확인한다. `—`는 빈 폴더나 0 B라는 뜻이 아니다. 양수의 **확인** 표시는 읽은 항목의 합계이며 전체는 미확인일 수 있다. 실제 빈 폴더를 완전히 읽었을 때만 `0 B`로 표시한다. 행을 선택하면 전체 경로와 범위 설명을 읽을 수 있다. 하위 포함 행끼리 더하면 중복 계산된다.

CSV의 숫자는 **확인된** 바이트/파일 수다. 함께 제공하는 폴더 분석 범위를 확인한다. JSON 보고서는 버전 2이며 `folder_coverage`에 `complete/excluded/incomplete/cancelled/unknown` 상태를 담는다. 이전 보고서는 그대로 남으며 기존 앱 DB는 변환할 필요가 없다.

## 처음 시험하거나 후보 표가 비어 있을 때

1. **관리 · 도구 → 시험 프로젝트 만들고 분석**을 누른다. 빈 후보 화면의 **시험 자료로 사용 흐름 익히기**도 같은 기능이다.
2. 새 시험 폴더를 만들 상위 위치를 선택한다. 기본 제안은 사용자 임시 폴더다. 기존 개인 프로젝트를 고를 필요가 없다. 앱은 `DevStorageManager-시험-...`라는 새 하위 폴더만 생성한다.
3. 자동 등록·실제 분석이 끝나면 **프로젝트·정리 후보** 탭에 `__pycache__` 행이 나온다. 한 번 클릭하고 **② 포함 파일 검토**를 누르면 정확한 경로와 내용을 볼 수 있다.
4. 정리하려면 먼저 **관리 · 도구 → 정리 환경 확인**을 통과해야 한다. 시험 자료도 승인/내용 검증을 우회하지 않는다. 원본 `demo_owned.py`, `pyproject.toml`, 보호 표식 `.git/KEEP.txt`는 정리하지 않는다.
5. 실행 후 결과/이력과 재분석을 확인한다. 복원은 Windows 휴지통에서 직접 한다. 목록 제거는 실제 시험 폴더를 없애지 않는다. 생성 중 실패/취소 후 남은 자료도 위치를 확인하고 직접 관리한다.

**관리 · 도구 → 사용 방법**에서 전체 순서/빈 표/복원/한계를 읽을 수 있다. 실제 프로젝트에 후보가 없다고 직접 `__pycache__`를 만들 필요는 없다. 시험 자료는 별도 폴더에 만든다.

## 실행 직후 결과

휴지통 작업 후 **정리 실행 결과** 창에서 기록된 상태, 성공으로 확인한 크기, 계획 전체 크기, 실제 관측한 디스크 여유 공간을 확인한다. 실패 이유/원래 경로/영수증도 선택·복사할 수 있다. 결과 기록을 읽지 못하면 수치나 성공을 추정하지 않는다. 미확정은 원래 경로와 Windows 휴지통을 확인해야 한다.

**이 작업 이력 보기**는 기존 검색을 지우고 해당 작업만 표시한다. **전체 이력 보기**로 범위를 되돌릴 수 있다. **프로젝트 다시 분석**은 등록 프로젝트를 읽기 전용으로 재분석한다. 정리 시도 뒤에는 앱을 다시 열어도 재분석 전까지 이전 후보를 실행할 수 없다. 이전 용량/큰 파일 기록은 과거 분석 시점의 값이다.

## 포함 파일 검토

후보를 선택하고 **② 포함 파일 검토**를 누르면 위쪽에 정확한 대상 폴더와 확인한 목록의 크기가 나온다. **포함 파일**에서 이름/경로를 검색하고 크기 열로 숫자 정렬할 수 있다. 행을 선택하면 아래에서 전체 경로와 정확한 바이트를 확인/복사한다. **근거·주의·실행 조건** 탭에서 분류 이유, 재생성 조건과 제한 이유를 읽는다.

검색 결과나 선택한 파일 몇 개만 지우는 기능이 아니다. 실행 대상은 위에 표시한 후보 폴더 전체다. 내용 검증과 환경 자격을 통과한 경우에만 확인 체크 후 이동 버튼이 활성화된다. 처음에는 체크하지 않으며 표시 오류나 불완전/미지원 후보는 실행을 제한한다. 확인한 목록은 최대 50,000개이며 제한을 넘으면 부분 목록과 제한 이유를 표시한다.

## 정리 이력 확인

**정리 이력**의 검색 칸은 전체 이력의 원래 경로와 실패 이유를 검색한다. `%`, `_`, `[`도 문자 그대로 찾는다. 검색은 250ms 뒤 실행되며 새 입력이 이전 검색을 취소한다. 한 번에 최대 200개이고 아래 **이전 페이지/다음 페이지**로 이동한다. 페이지 이동 중 새 작업이 앞에 끼어들지 않으며 최신 이력은 **이력 새로고침**으로 확인한다. 이력 조회는 별도 작업이라 분석/화면 입력을 막지 않는다. 오류 표시는 이력이 없다는 뜻이 아니다.

**정리 이력**에서 행을 선택하면 아래 상세 영역에 전체 원래 경로, 항목 결과, 전체 작업 상태, 긴 실패 이유, 확인된 휴지통 영수증 경로가 표시된다. 읽기 전용 문구를 선택·복사할 수 있으며 표와 상세 사이의 경계를 끌어 높이를 조절할 수 있다.

이동이 확인된 항목이라도 전체 완료 기록 저장이 실패하면 전체 작업은 중단으로 표시될 수 있다. 미확정은 성공이나 원본 보존을 보장하는 상태가 아니다. 원래 경로와 Windows 휴지통을 확인하고 다시 분석한다. 기록 오류가 표시되면 추가 정리를 중단한다. 앱은 영구 삭제나 자동 복원으로 전환하지 않는다.

## 폴더 안의 파일 확인

**폴더별 용량**에서 행을 선택하고 **선택한 폴더 내용 보기**를 누르거나 행을 더블클릭한다. 아무 행도 선택하지 않은 경우 **프로젝트 폴더 내용 보기**로 프로젝트 바로 아래 목록을 연다. 별도 창에서 하위 폴더를 더블클릭/열기 버튼으로 이동하고 **상위 폴더**로 돌아온다. 프로젝트 경계 밖으로는 올라가지 않는다.

파일을 선택하면 전체 경로와 크기를 아래 읽기 전용 칸에 표시한다. 이 동작은 파일 실행/미리보기/삭제가 아니다. 보호·제외·링크와 읽기 실패 항목은 열지 않는 이유를 표시한다. 분석 뒤 생긴 새 폴더는 다시 분석해야 열 수 있다. 한 폴더의 바로 아래 항목 최대 5,000개를 보관하며 검색은 그 목록에만 적용한다. 폴더의 하위 포함 크기는 원래 분석 표에서 확인한다. 현재 목록과 저장된 분석 시점은 다를 수 있다. 읽기 취소와 닫기를 사용할 수 있다.

## 실행

ZIP 전체를 새 폴더에 압축 해제하고 `DevStorageManager.exe`를 더블클릭한다. `_internal` 폴더를 옆에 유지한다. Python 별도 설치와 관리자 실행은 필요하지 않도록 묶었다. 이전 앱은 닫는다. 파일 서명과 깨끗한 별도 PC 시험은 아직 완료하지 않았다.

## 용량 확인

1. **폴더 추가**로 개발 프로젝트를 등록한다. 상단 선택기에서 프로젝트 이름을 고른다.
2. **선택 프로젝트 분석**을 누른다. 분석 중 **작업 취소**를 누를 수 있다. 결과 저장/불러오기는 완료를 기다린다.
3. 기본 결과는 **폴더별 용량**이다. 하위 포함 값이므로 행끼리 합산하지 않는다. 행 선택으로 전체 경로를 확인한다.
4. **큰 파일** 탭은 읽은 범위에서 용량이 큰 파일을 최대 500개 보관한다. 이름/경로를 검색하고 용량순 정렬 및 행 선택으로 정확한 경로를 확인한다. 파일 크기는 KB/MB/GB/TB(1 KB = 1,024 B)이고 툴팁에는 정확한 바이트가 있다. 큰 파일이라는 이유로 삭제 후보로 판정하지 않는다.
5. 후보가 없다면 선택하거나 정리할 항목이 없는 상태다. 캐시를 직접 만들 필요가 없다. 미분석·부분 결과·제외 범위는 화면의 설명과 **오류·제외 범위**를 확인한다.

큰 파일 목록은 전체 파일 목록이 아니다. 검색은 보관된 상위 500개 안에서 적용한다. 이전 분석에 파일 상세가 없으면 다시 분석해야 한다. 취소/읽기 실패/제외된 경로는 포함되지 않을 수 있다. 분석은 실시간 스냅샷이나 실제 디스크 할당량 측정이 아니다.

## 정리 후보 검토

**프로젝트·정리 후보** 탭에서 한 행을 선택한 뒤 **② 포함 파일 검토**를 누른다. 실제 경로·포함 파일·근거·주의·재생성 조건·실행 제한을 읽는다. 포함 파일 행 선택은 경로 확인이며 개별 파일 삭제 선택이 아니다. 후보가 없으면 이 단계를 진행하지 않는다.

시작할 때 정리는 비활성이다. **관리 · 도구 → 정리 환경 확인**은 앱이 새로 만든 시험 자료로 공유 보호 항목과 캐시 유형별 휴지통 연동을 점검한다. 사용자 프로젝트 코드를 실행하지 않는다. 시험 캐시는 휴지통에 남을 수 있고 원본/기록은 앱 데이터에 남는다.

공유 링크 경계·보호 경로·원본 보존을 통과하고, **해당 캐시 유형**의 휴지통 시험도 통과해야 실행 자격이 생긴다. Python 실행 캐시의 통과가 pytest 테스트 캐시를 승인하지 않는다. 사용자 추가 파일·지원하지 않는 JSON·수정된 표식·링크·변경된 대상은 실행을 제한한다. pytest의 실패/실행 순서 기록이 사라질 수 있다. 재생성 안내 명령은 자동 실행하지 않는다.

검토 창의 확인 체크는 처음에는 꺼져 있다. 개별 내용 검증 및 실행 자격을 충족하고 사용자가 확인해야 **③ 휴지통 이동**이 활성화된다. 현재 지원 대상은 검증된 Python 3.12 실행 캐시와 pytest 기본 캐시 형식이다. 가상환경/node_modules/빌드 폴더는 설명과 목록 검토만 지원한다.

## 도구·이력

- **관리 · 도구**에 프로젝트 목록 펼치기/목록 제거/제외 목록/이전 결과 비교/보고서/환경 결과/프로그램 정보가 있다. 목록 제거는 원본 폴더를 삭제하지 않는다.
- 보고서는 JSON, 폴더 CSV, 큰 파일 CSV 중 선택한다. 화면 검색과 무관하게 저장된 분석 범위를 내보낸다. 큰 파일 CSV에는 상한/전체 확인 파일 수/분석 상태를 포함한다. 기존 파일은 덮어쓰지 않는다.
- 정리 후 다시 분석한다. **정리 이력**은 성공/실패/취소/미확정을 구분한다. 이동 확인 파일 크기와 관측 여유 공간은 별도 값이며 휴지통 이동이 즉시 공간 증가를 뜻하지 않는다.
- 복원은 Windows 휴지통에서 원래 위치와 시간을 확인해 직접 수행한다. 앱은 자동 복원이나 휴지통 비우기를 제공하지 않는다.
- 이전 환경 점검 결과는 볼 수 있지만 재시작 후 실행 승인은 초기화된다. 점검 결과 복사는 직접 누를 때만 클립보드에 복사하며 전송하지 않는다.

DB/기록은 `%LOCALAPPDATA%\DevStorageManager`, 환경 점검 기록은 그 아래 `environment-tests\last-result.json`이다. Windows 10, 모든 DPI 배율, 정상 Windows의 pytest 캐시 수동 복원은 아직 미검증이다. 자세한 범위는 SUPPORT.md, RELEASE_AUDIT.md와 VALIDATION_0150.md를 참고한다.
