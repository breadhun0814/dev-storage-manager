# 휴지통 실행 검증 기록

## 0.3.2 환경 시험 수정

환경 시험의 mklink 인수를 단일 명령 문자열에서 별도 인수로 수정했다. 실제 echo로 인용부호 앞 역슬래시 혼입을 재현한 뒤 수정했다. 따라서 0.3.0/0.3.1의 환경 시험 실패가 모두 OS 제한 때문이었다고 단정할 수 없다.

수정 후 이 에이전트의 work 아래 직접 만든 시험 폴더로 qualify를 실행한 결과는 ready=false, 반환 코드 1, 실제 오류 '액세스가 거부되었습니다.'였다. 경계 보호가 확인되지 않아 휴지통 단계로 진행하지 않았다. 이 결과는 수정 후에도 현재 환경에 실제 생성 제한이 있음을 뜻하며, 일반 Windows 환경의 성공/복원 검증은 여전히 필요하다.

## 2026-10-30 로컬 결과

Send2Trash 2.1.0 및 pywin32 311 설치/modern 모듈 import 성공. Windows IFileOperation COM 객체 생성 성공(이 단계에서는 파일 작업 없음).

`scripts/verify_recycle.py`는 work 아래 고유 임시 프로젝트에 직접 만든 .py/pyc만 사용한다. 기존 프로젝트 입력은 받지 않는다. 소스 내용을 확인하고, 엄격한 캐시 계획을 만든 뒤 Shell 휴지통 요청을 시도한다. 휴지통을 비우거나 영구 삭제로 전환하지 않는다.

실제 시험에서 PreDeleteItem 전송 플래그는 `0x202`였다. 필수 `TSF_DELETE_RECYCLE_IF_POSSIBLE`이 없어 콜백에서 작업을 중단했다. 상태는 **실패**, 원본 .py 보존을 확인했다. 이 결과를 휴지통 이동 성공으로 해석하지 않는다. 시험 종료 시 이 스크립트가 직접 만든 임시 폴더만 정리된다.

현재 UI는 시작 시 휴지통 실행을 비활성화한다. 앱 내 '정리 환경 시험'으로 직접 만든 임시 junction의 경계 보호와 실제 휴지통 플래그·영수증·소스 보존을 모두 확인한 세션에서만 Python 3.12 캐시를 개별 검증 후 허용하도록 연결했다. 현재 에이전트 환경의 실제 시험 성공은 여전히 확인하지 못했다. 자세한 동작은 SUPPORT.md에 기록한다.

## 구현된 방어

최신 소스 추가: PreDelete 콜백의 거부를 Shell이 무시하고 성공을 반환하는 경우에도 성공 처리하지 않는다. PostDelete의 대상 경로와 휴지통 플래그도 확인한다. 실제 삭제를 호출하지 않는 COM 프로토콜 대역 3개 시험으로 차단 동작을 검증했다. 현재 제공된 preview 이후 변경이다.

- 직접 작성한 Windows 어댑터는 Send2Trash의 COM sink 기반을 사용하며 legacy dispatcher를 호출하지 않는다.
- 로컬 고정 드라이브만 허용하고 UNC/이동식 드라이브를 거부한다.
- PreDelete 콜백에서 정확한 대상 경로·휴지통 플래그·즉시 재검증을 요구한다.
- PostDelete의 성공 HRESULT와 새 휴지통 항목을 모두 요구한다. 원래 경로가 남아 있으면 성공으로 표시하지 않는다.
- 실패/취소/미확정 상태를 성공과 구분한다. 실행 시도 후 경로가 사라졌지만 영수증이 없으면 미확정이다.
- 서비스는 작업 전에 SQLite 상태를 커밋하고, 실행 전/콜백 시점에 목록·메타데이터·내용 해시를 재검증한다.
- 재시작 시 실행 중이던 항목은 미확정, 대기 항목은 실행 전 취소로 구분한다.
- Python 캐시는 현재 3.12 pyc 파일명·magic/header·대응 .py 원본을 검증한다. 알 수 없는 파일·하위 폴더·하드링크·링크는 차단한다.
- pytest 검증 규칙은 준비 중이다. 실제 이동 지원 유형으로 확정하지 않는다.
