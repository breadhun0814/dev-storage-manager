# 개발 저장공간 관리자 — 계획과 범위

저장소명 `dev-storage-manager`. 1인 개발 약 20주, 사용자의 일일 검토 시간 3~4시간을 다른 프로젝트와 나누는 조건으로 진행한다. Windows 11 x64 우선, Windows 10은 실제 시험 후 지원 여부를 표시한다. 일반 사용자 권한, 로컬 전용이며 회원가입·업로드·외부 AI API가 없다. 다른 프로젝트 코드는 수정하지 않는다.

## 사용 흐름과 화면

프로젝트 등록 → 읽기 전용 분석 → 전체/폴더별 논리적 크기 → 후보 근거·포함 파일 검토 → 사용자가 직접 선택 → 실행 직전 재검증 → 휴지통 이동 → 성공/실패와 관측 디스크 여유 공간 확인.

- 프로젝트 목록: 이름·경로·마지막 분석·상태, 분석/열기/목록 제거. 목록 제거는 원본을 변경하지 않는다.
- 결과: 폴더 크기·파일 수, 분류·후보 이유·주의, 검색·정렬·제외, 오류·불완전 범위, 취소.
- 정리 검토: 정확한 경로·포함 항목·논리적 크기·근거·재생성 조건·명시적 실행.
- 이력: 시간·원래 경로·성공/실패·실패 이유·Windows 휴지통에서 수동 복원 안내. 구현하지 않은 자동 복원은 표시하지 않는다.

## 단계

| 기간 | 범위 |
|---|---|
| 1~2주 | 구조, 문서, 임시 폴더 시험, 등록과 기본 창 |
| 3~5주 | 실제 분석·진행·취소·권한/링크 오류·폴더별 집계 |
| 6~8주 | Python/JavaScript/Java 식별, 근거 기반 후보, 제외 목록, 결과 저장 |
| 9~11주 | 정리 계획·변경 재검증·휴지통·실패/중단 이력·보호 시험 |
| 12~14주 | 재분석 비교·이력·보고서·재생성 안내 |
| 15~17주 | 큰 폴더 실측·메모리/반응성·유형별 지원 확정 |
| 18~20주 | Windows 배포·깨끗한 일반 사용자 환경 시험·한국어 설명서 |

현재 구현은 첫 단계의 읽기 전용 분석 수직 기능에 한정한다. 향후 기간은 추정이며 완료를 의미하지 않는다.

## 판별과 정리 정책

Python: pyproject.toml, requirements 파일 등; JavaScript: package.json과 잠금 파일; Java: pom.xml, build.gradle 등. 코드·설치 스크립트를 실행해서 분석하지 않는다. 이름만으로 삭제 가능하다고 판정하지 않는다.

첫 활성화 대상은 근거가 명확한 __pycache__·pytest 캐시부터 검증한다. pyvenv.cfg가 확인된 가상환경, 프로젝트와 연결된 node_modules, Maven target·Gradle build는 사용자 수정 가능성과 재설치/빌드 조건을 설명하고 유형별 검증 이후 지원한다. 재생성 명령은 안내만 한다. 초기 선택은 모두 해제한다.

등록한 폴더만 탐색한다. 드라이브 루트·시스템·.git·앱 데이터·실행 환경을 보호한다. 링크/reparse point를 기본적으로 따르지 않는다. 정리 대상 내부 링크·경계 불명확·분석 후 변경은 정리를 제한한다. 부모/자식 중복 선택은 계획 단계에서 제거한다. 휴지통 실패를 영구 삭제로 대체하지 않으며 원본 삭제 우회 경로를 만들지 않는다. 작업 전 상태를 기록하고 재시작 시 미확정 작업을 구분한다.

논리적 파일 크기와 실제 디스크 사용량은 다르다. 하드링크는 파일 경로별 크기에 포함된다. 휴지통 이동 크기와 실제 관측 여유 공간은 별개로 표시하며 휴지통을 자동으로 비우지 않는다.

## 첫 배포 완료 조건

등록·분석·후보 검토·휴지통 이동 실동작, 후보 근거/미지원 설명, 실패의 정확한 표시, 원본 보호 시험, Windows 실행 배포물, 설치/실행/시험/제한 문서가 모두 필요하다. 현재 0.1.0은 이 배포 완료 조건을 충족하지 않는다.
