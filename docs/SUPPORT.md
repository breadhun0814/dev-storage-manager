# 지원 범위 · 0.15.0 시험 버전

포함 파일 목록도 분석 결과와 경로·식별 지문·파일 수·논리적 크기를 대조한다. 누락/중복 등 불일치하면 정리를 차단하고 재분석을 안내한다. 상세는 VALIDATION_0150.md, 전체 완료 기준과 미검증 범위는 RELEASE_AUDIT.md에 기록한다.

폴더 검색·정렬은 스냅샷 메타데이터의 별도 인덱스 작업이며 디스크를 다시 탐색하지 않는다. 인덱스/역매핑의 추가 메모리가 필요하고 모든 CPU/DPI에서의 응답 시간을 보장하지 않는다. 표시 오류는 0개 성공으로 처리하지 않으며 검색/정렬을 바꿔 다시 시도할 수 있다.

폴더별 용량/보고서는 확인분과 전체 미확인을 구분한다. 취소된 결과에는 폴더별 방문 완료 정보가 없어 보수적으로 부분 표시한다. 보호/링크/사용자 제외는 집계에 포함하지 않는다. 읽은 범위가 완료되어도 논리적 크기는 실제 디스크 사용량과 다를 수 있다. JSON 보고서 형식은 버전 2이며 앱 DB 결과 형식은 유지한다.

시험 프로젝트는 별도 새 하위 폴더의 고정 자료만 생성하고 실제 등록/분석한다. 개인 원본을 실행/복사/덮어쓰지 않으며 취소/실패 후 새 자료도 자동 삭제하지 않는다. 일반 후보와 같은 보호/환경/내용 검증을 적용한다. 시험 생성·검토의 통과를 실제 휴지통 이동/수동 복원 또는 환경 자격으로 확대하지 않는다.

실행 결과는 기록된 항목별 상태/이동 확인 크기/별도 관측 여유 공간을 구분한다. 결과 조회 실패는 성공/0 B/원본 보존으로 단정하지 않는다. 정리 시도 전에 재분석 필요를 기록하고 이전 후보 사용을 차단한다. 임시 자료의 rename 기반 프로토콜 대역과 기록 실패 주입 검사는 실제 휴지통/복원 검증과 별개다.

포함 파일 검토는 최대 50,000개 확인 목록의 가상 표/별도 검색·숫자 정렬을 지원한다. 표시 검색과 행 선택은 실행 계획을 바꾸지 않으며 개별 파일 선택 삭제가 아니다. 불완전 목록/미지원 유형/실패한 내용 검증/미통과 환경의 정리는 활성화하지 않는다. 5만 개 합성 메타데이터의 Qt 표시/검색 측정은 실제 디스크 탐색·내용 증거 검증·휴지통 이동 성능 측정과 별개다.

이력 조회는 읽기 전용 작업 스레드/페이지당 최대 200개, 전체 경로·실패 이유 검색을 지원한다. 새로고침 전에는 새 작업 삽입으로 페이지가 밀리지 않으며 항목 상태는 각 조회 시점의 값이다. 이동 확인 크기는 해당 작업 전체의 성공 항목 합계로, 현재 검색/페이지와 별개다. 합성 10만 건의 조회/취소 측정은 실제 장기 사용자 DB나 전체 프로세스 메모리 측정이 아니다. 800×600 Qt offscreen 화면을 확인했으며 모든 실물 모니터/DPI 검증은 아니다.

폴더 내용 탐색은 등록된 분석의 경계 안에서 바로 아래 목록을 읽는 기능이다. 파일 내용 열기/실행/삭제 기능은 아니다. 최대 5,000개 제한, 현재 제외/보호/링크/권한 오류 및 취소 상태를 표시한다. 실제 모든 DPI 검증이나 새 캐시 유형의 정상 Windows 휴지통/복원 검증을 확대하지 않는다.

Python 캐시의 대응 원본도 내용 검증에 포함하며 일반 파일·비링크·비하드링크·8 MiB 한도를 적용한다. 같은 크기/같은 수정 시각이어도 검토 후 내용 해시가 달라지면 정리를 중단한다.

| 항목 | 상태 |
|---|---|
| Windows 11 x64 / Python 3.12 / Qt Widgets | 현재 제한된 환경의 실행·분석·배포 시작 검사, 사용자 0.6.1 환경 시험 통과 보고 |
| Windows 10 / 깨끗한 별도 설치 / 모든 DPI | 미검증, 지원 확정 아님 |
| 분석·취소·오류·제외·폴더 용량 | 실제 임시 자료 검사 |
| 큰 파일 상위 500개·검색·숫자 정렬·저장·CSV | 실제 임시 자료와 Qt 흐름 검사, 전체 파일 목록은 아님 |
| 저장 결과 읽기·보고서·비교 | UI 밖의 작업 스레드, 입력 반응 검사 |
| Python 3.12 실행 캐시 | 공유 보호와 자체 유형의 실제 런타임 휴지통 시험 + 개별 내용 검증 + 직접 확인 후 실행 |
| pytest 기본 테스트 캐시 | 같은 조건을 별도 유형으로 적용. 고정한 pytest 9.0.2의 실제 생성 형식 검사. 정상 Windows의 이 유형 이동/복원은 독립된 검증 항목 |
| 가상환경 / node_modules / Maven·Gradle 산출물 | 근거·주의·재생성 조건·포함 목록 검토만. 정리 미지원 |
| 자동 복원 / 휴지통 비우기 / 영구 삭제 대체 경로 | 제공하지 않음 |

`.git`, 앱 데이터/실행 환경/보호 경로, 링크/reparse point를 보호한다. 읽기 실패와 제외 범위는 결과에 표시하고 불완전 결과를 전체 성공으로 처리하지 않는다. 하드링크/추가 파일/알 수 없는 캐시 구조는 내용 검증에서 제한한다. 검사와 OS 작업 사이의 모든 경합을 원자적으로 배제하는 보장은 없으므로 분석/정리 중 프로젝트 작업을 중단한 상태가 적합하다. OS 호출은 즉시 취소되지 않을 수 있다.

포함 파일 검토는 50,000개, 개별 캐시 내용 검증은 8 MiB 한도다. pytest 플러그인의 사용자 캐시/추가 파일, 지원하지 않는 버전의 stepwise 형식은 제한한다. 캐시 표식과 형식은 재생성 가능성의 근거이며 '안전한 파일' 보증이 아니다. 테스트 실패 이력과 순서 정보가 사라질 수 있다.

사용자는 0.6.1 수정 후 링크/보호/시험 캐시 휴지통/원본 보존 통과를 보고했다(USER_VALIDATION.md). 이 근거를 에이전트의 독립 재현, pytest 유형의 실제 성공, 개인 프로젝트 전체 흐름 또는 수동 복원 완료로 확대하지 않는다. 에이전트 실행 환경의 실제 Shell은 recycle 플래그를 제공하지 않아 해당 진단은 실패로 보존한다.

기존 0.6.x가 읽는 기본 DB 결과 구조는 유지하고 큰 파일은 별도 테이블에 분석 해시와 함께 저장한다. 이전 앱이 결과를 다시 쓰면 낡은 파일 상세를 표시하지 않는다. 이전 환경 기록으로 실행 승인을 복원하지 않는다. GitHub 업로드는 보류한다.
