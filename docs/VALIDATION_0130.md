# 0.13.0 부분 분석의 크기·파일 수 표시

전체 pytest **176 passed, 3 skipped** (`work/pytest-0130-final-b`, 18.32초). 링크 3종 생성 거부는 통과로 계산하지 않는다. 임시 시험 자료만 사용했다.

## 검증

- 읽기 오류/제외의 해당 폴더와 부모 전파, 정상으로 읽은 형제 폴더 구분, Windows 경로 대소문자 비교, 취소/위치 없는 오류의 보수적 표시를 검사했다.
- 읽기 실패로 확인분 0은 크기/파일 수 모두 —이며 실제 빈 폴더는 0 B/0이다. 양수 확인분 표시 뒤에도 원시 바이트 숫자로 정렬한다.
- 실제 임시 폴더의 scandir 오류를 주입하고 SQLite 저장/재열기 후 UI와 CSV/JSON의 범위를 검사했다. 실제 임시 Windows DACL 읽기 거부에서도 해당 폴더 —/불완전 표시를 확인하고 원래 DACL을 복구했다.
- 전체 요약/카드가 불완전 0을 0 B로 표시하지 않고 전체 미확인을 명시하며 선택 상세도 확인분과 범위를 설명한다. 후보 크기에도 확인분 의미를 적용한다. 정리 판정/실행 자격을 바꾸지 않았다.
- 실제 Qt offscreen 800×600 화면을 확인했다(`work/coverage-0130-800.png`). 범위 열과 요약/선택의 미확인 설명을 읽을 수 있다. 화면 자료의 오류는 합성 표시이며 실제 DACL 검사는 별도다. 모든 DPI 검증은 아니다.

보고서 JSON schema_version=2의 folder_coverage와 CSV 추가 범위 필드를 검사했다. 수치는 확인된 논리적 합계이며 전체 미확인의 0을 실제 전체 0으로 해석하지 않는다. 앱 DB의 기존 결과 형식은 유지한다.

소스 `work/startup-0130-source.json`과 EXE `work/startup-0130-frozen.json` 자체 검사 모두 passed=true/0.13.0, EXE mode=frozen이다. 기존 실제 분석/표/이력/검토/취소 결과/시험 프로젝트 검증에 partial_zero_displayed_as_unknown=true를 추가했다. 이 표시 자체 검사는 합성 불완전 모델이며 실제 권한 시험의 대체가 아니다. 정리 비활성/자격 없음 상태를 유지하고 실제 휴지통 이동은 하지 않는다.

깨끗한 Windows 설치/서명, Windows 10, 모든 DPI, 새 pytest 유형의 정상 Windows 실제 이동/수동 복원은 미검증이다. 사용자 보고와 에이전트의 차단/skip을 구분하며 GitHub 업로드는 보류한다.
