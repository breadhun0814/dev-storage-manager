# 기술 결정

## 0.15.0 포함 목록을 별도 검증

앞뒤 분석 지문 일치만으로 그 사이의 포함 목록을 신뢰하지 않는다. 목록 열거에서 관측한 직접 엔트리/디렉터리 식별 정보로 scanner와 같은 지문을 구성하고 분석 지문·개수·크기·고유 경로와 대조한다. 같은 크기의 항목 대체/중복은 합계만으로 판별할 수 없으므로 전체 지문도 필요하다. 파일 시스템에 쓰거나 지원 캐시 유형을 확대하지 않는다.

누락된 개인 자료를 가진 임시 후보가 기존 검토를 통과하는 결함을 먼저 재현했다. 누락/중복을 주입한 검사는 수정 후 모두 거부하며 원본은 보존한다. 이는 논리 회귀 검사이고 모든 OS 경합의 원자성 증명은 아니다. 기존 내용 증거와 실행 직전 검증을 유지한다. 상세는 VALIDATION_0150.md, 원래 완료 기준 전체 대조는 RELEASE_AUDIT.md에 기록한다.

## 0.14.0 폴더 검색/정렬

10만 행의 Qt 정렬은 Python data 콜백을 비교 과정에서 반복 호출해 UI를 오래 점유했다. 기존 원본 FolderModel은 유지하고 QAbstractProxyModel의 행 인덱스를 별도 QThread에서 계산한다. 검색은 전체 경로의 Unicode casefold 리터럴 검색이고 숫자는 원시 바이트/파일 수로 정렬한다. 초기 무필터/무정렬은 range를 사용한다. 계산한 정방향/역방향 매핑을 UI에서 모델 reset으로 교체한다.

새 검색/정렬/원본 reset은 기존 작업을 취소하며 세대·검색·정렬 조건이 일치한 결과만 반영한다. 계산 중에는 이전 목록일 수 있음을 표시하고 표시 오류는 빈 성공으로 처리하지 않는다. 선택은 reset 때 해제하고 전체 경로 안내도 지운다. 경로 매핑을 통해 파일 보기 대상이 정렬 전의 잘못된 행을 가리키지 않게 한다. 앱은 취소 후 인덱스 작업 종료까지 기다려 닫는다. 파일 작업과 정리 자격은 변경하지 않는다.

UI 타이머와 Qt 모델 계약 검사, 실제 스레드 ID 확인, 10만 행 전체 정렬 순서/필터 결과를 기존 구현과 대조한다. 시간 측정은 모델/인덱스 작업만 포함하며 표 그리기/실제 디스크 탐색/Qt native/RSS와 구분한다. 추가 Python 인덱스 메모리 비용도 기록한다.

## 0.13.0 확인분과 전체 미확인

기존 결과의 status/issues에서 범위를 파생하므로 Folder/SQLite 기본 JSON을 바꾸지 않는다. 읽기 오류는 해당 경로와 상위 폴더에 전파하고 읽은 형제 폴더는 구분한다. 제외도 해당 범위를 포함한 부모에 전파하며 읽기 실패가 제외보다 우선한다. 취소 결과는 기존 형식에 방문 완료 여부가 없으므로 모든 폴더를 보수적으로 부분 결과로 표시한다. 오류 위치가 없거나 루트 밖이면 전체 범위 미확인이다.

불완전·제외·취소 확인분 0을 빈 폴더로 단정하지 않고 —로 표시한다. 양수는 확인분으로, 읽은 전체 범위가 확인된 빈 폴더만 0 B로 표시한다. 원시 바이트/파일 수는 그대로 남겨 숫자 정렬/집계가 문자열에 의존하지 않게 한다. 요약/카드/선택/후보에도 같은 의미를 적용한다. 행끼리 합산해 하위 크기를 중복 계산하지 말라는 안내를 유지한다.

보고서는 JSON schema_version 2에 folder_coverage를 추가하고 CSV도 확인된 바이트/파일 수와 폴더별 범위/전체 미확인 여부를 기록한다. 숫자 0을 실제 전체 크기 0으로 해석해서는 안 된다. DB 형식 변경이 아니므로 기존 저장 결과도 파생 범위를 다시 계산한다. 경로 비교는 lexical Path이며 링크를 resolve하거나 디스크를 재탐색하지 않는다. 공통 상태는 상수이고 예외 범위만 사전으로 보관한다.

## 0.12.0 독립 시험 프로젝트

후보가 없는 실제 프로젝트에 캐시를 만들게 하는 대신 사용자가 선택한 상위 위치에 mkdtemp로 새 하위 폴더를 만든다. 부모의 링크/보호 경계를 검증하고 directory_guard 아래에서 파일을 xb로 독점 생성한다. 개인 파일을 복사하지 않으며 정상 등록 후 스캐너/검토/정리 정책은 일반 프로젝트와 같다. 취소/오류로 일부 생성된 새 폴더는 원본 삭제 우회 없이 그대로 남기고 위치를 안내한다.

실제 캐시는 앱의 고정 바이트만 메모리에서 컴파일하고 marshal로 저장한 checked-hash pyc다. 사용자 소스/설치 스크립트/코드 객체를 실행하지 않으며 캐시를 import하지 않는다. 헤더는 [PEP 552](https://peps.python.org/pep-0552/)에 따르고 고정한 Python 3.12의 py_compile CHECKED_HASH 출력과 전체 바이트를 대조했다. 원본에 실행 시 실패하는 코드를 넣은 시험도 생성/분석/증거 검사에서 실행되지 않음을 확인한다.

시험 자료는 실행 자격을 부여하지 않는다. 초기 미선택/정리 비활성, 타입별 환경 시험, 내용 변경 검증, 직접 확인을 유지한다. .git/KEEP.txt는 실제 저장소를 만들기 위한 것이 아니라 보호 제외를 확인하는 고정 표식이다. 앱이 이 파일을 정리하지 않는 것을 검사한다. 도움말은 실제 한국어 동작 이름과 범위를 안내하며 진행 중 작업이 있으면 도움말의 생성 버튼을 비활성화한다.

## 0.11.0 실행 결과와 재분석 필요 상태

정리 스레드가 단순 작업 ID 대신 한 SQLite 읽기 스냅샷의 결과를 전달한다. 상태별 개수와 전체 계획 크기/성공 영수증이 확인된 항목의 크기는 전체 작업을 집계하고 경로 상세는 200개로 제한한다. 합계/상태/영수증 형식이 잘못되면 결과 조회 실패로 처리한다. 예외 후에도 남아 있는 기록을 읽을 수 있으면 중단/미확정을 표시하고, DB를 읽지 못하면 수치 미확인을 표시한다. 경로 소멸만으로 성공을 만들어내지 않는다.

UI는 결과 창과 작업 ID 필터가 걸린 이력으로 연결하고 기존 경로 검색/페이지 경계를 갱신한다. 과거 작업이 앞뒤에 있어도 방금 작업의 결과가 검색 조건에 숨지 않는다. 전체 이력 복귀를 명시한다. 재분석 버튼은 선택했던 등록 프로젝트를 다시 분석하며 정리 버튼을 자동 실행하지 않는다.

파일 요청 전 등록 프로젝트의 needs-analysis 상태를 DB에 커밋한다. 이 쓰기가 실패하면 OS 이동을 요청하지 않는다. 취소/실패도 시도 후에는 다시 분석하게 하며, 이전 저장 결과는 크기 확인용으로 남기고 후보/실행 계획은 다시 사용하지 않는다. 이 상태를 앱 재시작 뒤에도 적용한다. 실행 이후 이 쓰기에 의존하면 OS 성공 뒤 저장 실패로 이전 후보가 살아날 수 있기 때문에 앞서 기록한다.

디스크 여유 공간도 directory_guard로 경계를 확인한 등록 경로에서만 관측한다. 검사 실패는 None으로 유지하며 다른 경로를 따라가거나 0으로 표시하지 않는다. 이동 크기와 디스크 여유 공간은 독립된 관측값이며 휴지통 자동 비우기는 없다.

## 0.10.0 포함 파일 검토

검토 결과는 이미 최대 50,000개로 제한되어 있으며 이를 늘리거나 불완전/미지원 후보를 승인하지 않는다. 파일마다 QTreeWidgetItem을 만드는 대신 QAbstractTableModel이 결과 목록과 행 인덱스를 참조한다. 상대 경로/용량 문자열은 보이는 행에서 계산한다. 인덱스 검색과 원시 바이트 숫자 정렬은 별도 QThread에서 수행하고 입력은 200ms 대기 후 적용한다. 검색은 확인한 목록만 대상으로 하며 전체 파일 시스템을 새로 읽지 않는다.

검토 UI를 별도 ReviewDialog로 분리한다. 전체 대상/총 크기와 포함 파일, 근거·주의·재생성 조건, 명시적 동의를 구분한다. 검색/정렬은 표시 인덱스만 바꾸며 계획·원본 파일·실행 대상 폴더를 변경하지 않는다. 파일 행은 경로 확인용이고 체크 삭제 기능이 아니다. 검증 실패/환경 미통과/계획 없음이면 실행을 제한하며 표시 오류도 확인을 해제한다. 정상 재표시 후에도 동의를 자동 복원하지 않는다.

닫기는 인덱스 작업 취소 후 QThread 종료를 기다리고, 앱 종료도 검토 창 작업을 포함한다. 완료된 검토 창은 삭제하여 큰 목록을 여러 번 열 때 메모리가 누적되지 않게 한다. 800×600 부모에서는 776×568 창 안에 동의/실행/닫기를 유지하고 상세 텍스트와 파일 표는 각각 스크롤한다. 독립 EXE 시작 검사에 실제 임시 파일 2개의 읽기 전용 검토/미선택/정리 비활성을 포함한다. 이 표시 자체 검사는 정리 유형의 실행 자격을 증명하지 않는다.

## 0.9.0 이력 조회와 작은 창

이력 조회는 read-only URI 연결과 별도 QThread에서 수행한다. 읽기 연결은 테이블 생성/복구를 하지 않으며, 초기 정리 테이블이 모두 없는 레거시 DB만 빈 이력으로 취급한다. 일부 테이블/형식 오류와 잠김은 실패로 표시한다. SQLite VM 진행 콜백으로 취소를 확인하고 연결마다 짧은 busy timeout을 둔다. 진행 중 파일 작업의 기록 쓰기 연결과 분리한다.

한 SQLite 읽기 트랜잭션 안에서 총수·한 페이지·해당 작업 전체 이동 확인 크기를 읽는다. 페이지당 200개, 내부 API 최대 500개다. 첫 조회 시 jobs.rowid 상한을 고정하여 새 작업 삽입이 기존 페이지를 밀지 않게 한다. 새로고침/검색 변경은 상한을 갱신한다. 상태는 각 조회 시점의 값이며 여러 페이지 전체를 과거 상태에 고정하지 않는다. Unicode casefold와 instr의 바인딩 인수로 경로/실패 이유의 리터럴 검색을 구현한다. 검색 결과에 보이지 않는 같은 작업의 성공도 전체 이동 크기 합계에 포함한다.

검색 입력은 250ms 뒤 조회하고 이전 조회를 취소하며 오래된 결과를 버린다. 창 종료는 읽기 작업 종료와 연결 해제 후 완료한다. 정리 완료 상태는 정리 작업 스레드에서 해당 job 한 행으로 읽어 전달하고 UI에서 모든 이력을 재조회하지 않는다.

QTabWidget의 기본 heightForWidth가 숨겨진 페이지의 선호 높이까지 요구해 작은 창에서 아래 버튼을 밀어냈다. 활성 페이지의 최소 레이아웃 높이로 계산하는 ResultTabs를 사용한다. 이력은 전체 프로젝트 대상이므로 프로젝트 선택기/정리 자격 배너를 숨기되 진행 상태와 분석 취소는 유지한다. 상태·실패 열은 남은 폭을 나누고 전체 경로/시각은 상세/툴팁으로 보존한다. 복원 안내는 키보드로도 열 수 있는 명시적 링크로 제공한다.

## 0.8.1 작업 기록 실패와 중단

운영체제 요청 전 running 상태를 커밋하지 못하면 파일 작업을 하지 않는다. 기록의 누락/잘못된 전이/영수증 없는 성공을 거부하고 전체 완료 상태가 모든 항목 결과와 일치하는지 검사한다. 기록 쓰기는 백엔드 예외 처리 바깥에 두어, 성공 기록 실패가 일반 휴지통 실패로 바뀐 뒤 다음 항목을 실행하지 않게 한다.

기록 오류는 해당 작업 전체를 중단한다. running은 보수적으로 unknown, 미시작 pending은 cancelled로 회복하며 확인된 succeeded/failed는 덮어쓰지 않는다. 복구의 모든 갱신은 한 SQLite 트랜잭션으로 묶는다. 중단 기록마저 실패하면 오류를 전파하고 추가 요청을 하지 않는다. 저장 기능이 회복된 재시작에서 기존 선기록을 복구한다. 경로가 사라졌다는 이유만으로 성공을 추론하지 않는다.

운영체제 요청 전의 사용자 취소만 '실행 전 취소'다. 요청 이후 응답을 잃고 원래 경로가 없으면 unknown으로 남긴다. 전체 완료 기록 실패와 확인된 개별 이동은 다른 상태이므로 UI 상세에서 둘을 함께 표시한다. 이력 정렬은 시간 문자열의 동일 초/시간대 변경에 의존하지 않고 작업 삽입 순서의 역순을 사용한다.

## 0.8.0 폴더 내용 탐색

용량 분석의 선택 폴더에서 현재 직접 파일/하위 폴더를 별도 읽기 전용 작업으로 읽는다. 등록된 현재 분석의 폴더 집합과 경계, 최신 제외 목록, 보호 경로를 검사하고 directory_guard로 모든 경로 구성요소의 reparse/실제 경로를 검증한다. 자식 stat은 follow_symlinks=False다. 파일 내용은 읽거나 실행하지 않는다.

목록은 5,000개 상한이며 검색/정렬은 표시 목록에 한정된다. 폴더 크기나 읽기 실패를 0 B로 오인시키지 않고 크기 미확인을 —로 표시한다. 분석 후 새 폴더는 재분석 전 이동을 제한한다. 탐색은 현재 상태, 분석 표는 분석 시점이라는 차이를 안내한다. 창을 닫으면 진행 중 읽기에 취소를 보내고 뒤늦은 결과가 창을 다시 열지 않게 한다. 탐색 데이터는 임시이며 DB/원본에 기록하지 않는다.

Python 캐시의 증거 해시는 pyc 바이트와 대응 .py 내용 해시를 함께 포함한다. 시간 기반 pyc 헤더가 같은 초/파일 크기의 원본 편집을 구분하지 못하므로, 검토 이후 동일 크기·복원된 수정 시각의 변경도 내용 해시로 차단한다. 원본도 일반 파일/비링크·비하드링크/8 MiB 한도/열기 전후 식별 검사를 적용한다. 원본을 실행하거나 수정하지 않는다.

## 0.7.0 묶음

- 큰 파일은 모든 파일 경로를 메모리에 쌓지 않고 500개 최소 힙으로 보관한다. 수집은 기존 읽기 전용 분석과 같은 경계/제외/취소 규칙을 따른다. 큰 파일 목록은 삭제 판정이 아니다.
- 기존 DB 기본 JSON을 유지하고 파일 상세는 별도 SQLite 테이블 + 기본 분석 해시로 연결한다. 레거시 앱의 재저장이나 손상된 부가 데이터가 오래된 파일을 현재 결과로 보이게 하지 않는다.
- 저장 결과 파싱도 LoadWorker에서 수행한다. 검토는 현재 읽은 결과를 사용하고 실제 실행 전 파일시스템을 재검증한다.
- Windows의 DirEntry 디렉터리 시각은 오래된 값일 수 있으므로 부모에서는 이름/유형만, 하위 자체 지문에서는 lstat 식별과 내용을 기록한다. 하위의 교체/추가/링크 검증은 유지한다.
- pytest 캐시는 검토한 기본 메타데이터 형식만 허용하고 실행 자격은 캐시 유형별 실제 런타임 시험과 공유 보호 통과의 교집합이다. 검토된 코드/단위 검사와 정상 Windows의 실제 이동·수동 복원 근거를 구분한다.
- pytest의 사용자 플러그인은 임의 JSON/파일을 캐시에 저장할 수 있으므로 알려진 기본 키만 검사한다. 공식 설명: https://docs.pytest.org/en/stable/how-to/cache.html

## 0.6.2 빈 후보 결과 안내

빈 결과를 '후보 없음'으로 일괄 표현하지 않는다. 미분석·부분 결과·제외 범위·파일 0개·완료된 범위의 후보 없음을 구분한다. 빈 표와 실행 불가능한 선택 지시를 감추고 용량 보기로 연결한다. 실제 프로젝트에 캐시를 생성하거나 이름만으로 후보를 채우지 않는다. 기존 Python 캐시 정리 정책과 증거 검증은 유지한다.

## 0.6.1 Windows 폴더 이동 결과 판정

Microsoft SDK sherrors.h에서 0x00270008은 COPYENGINE_S_DONT_PROCESS_CHILDREN 성공/정보 코드임을 확인했다. 사용자 실측 PostDeleteItem은 해당 코드와 recycle 플래그(0x282), 영수증을 제공했다. 0이 아닌 값을 무조건 실패 처리하던 앱의 버그를 수정한다. 모든 양수 HRESULT를 완료로 확대하지 않고 PostDeleteItem은 S_OK/0x00270008 두 값만 허용하며, 나머지 완료 증거와 실패 veto 검사는 유지한다. PerformOperations 전체 작업 결과와 중단 여부는 별도 검사한다.

- https://raw.githubusercontent.com/microsoft/win32metadata/main/generation/WinSDK/RecompiledIdlHeaders/um/sherrors.h
- https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itransfersource-recycleitem
- https://learn.microsoft.com/en-us/windows/win32/api/winerror/nf-winerror-succeeded

## 0.6.0 단계별 환경 진단

링크 생성 실패가 휴지통 실패 원인까지 가리지 않도록 새로 생성한 시험 캐시의 진단을 독립적으로 수행한다. 대상은 함수 내부에서 만든 fixture에 한정되고 원본 보호/내용 검증/엄격한 Windows recycle 어댑터를 그대로 사용한다. 일반 정리의 준비 상태는 네 필수 단계가 전부 통과할 때만 참이다. 저장된 결과는 실행 승인을 절대 복원하지 않는다. JSON 입력은 512 KiB로 제한하며 잘못된 기록은 무시한다. 테스트 대역의 이름 변경은 휴지통 검증으로 주장하지 않는다.

Microsoft 문서의 FOFX_RECYCLEONDELETE와 PostDeleteItem 영수증 계약을 확인했다. 현재 관측한 flags=0x202를 임의로 휴지통 성공으로 해석하지 않으며 플래그 확인을 완화하지 않는다.
- https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags
- https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem

## 0.5.0 실제 사용 피드백

- 작은 창은 선택기와 관리·도구 메뉴로 입력을 압축하고 결과 공간을 우선한다. 더 작은 화면은 전체 스크롤로 접근하며 검토 창도 스크롤을 지원한다.
- KB/MB/GB/TB는 1,024 배율이며 기준을 안내한다. 데이터/보고서/숫자 정렬은 원시 바이트를 유지한다.
- 포함 파일 선택은 확인용이다. 부분 파일 삭제를 기존 폴더 단위 정리 계획에 임의로 추가하지 않는다.
- Microsoft PreDeleteItem 문서는 실패 HRESULT가 작업을 취소한다고 명시한다. recycle 플래그 확인과 veto 보존을 유지한다. 실제 환경 시험이 junction 생성에서 거절되었으므로 제한을 우회하지 않고 실패 원인과 로컬 진단을 개선한다.
- 근거: https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem

## 0.2.0 추가

Windows에서는 탐색 중 조상 디렉터리 핸들을 유지한다. FILE_LIST_DIRECTORY|FILE_READ_ATTRIBUTES, share READ|WRITE, BACKUP_SEMANTICS|OPEN_REPARSE_POINT를 사용하고 reparse 속성 및 GetFinalPathNameByHandleW 결과를 확인한다. 탐색 이후 핸들은 즉시 닫는다. 임시 폴더 이름 변경 차단은 시험했지만 실제 junction 경합/네트워크 파일 시스템 시험은 미완료다. 휴지통 호출과의 원자성은 제공하지 않는다.

후보는 분석 중 관측한 일반 파일 표식과 연결 관계로 판별한다. 설정 파일은 실행/임포트하지 않는다. 캐시 후보에도 사용자 파일이 있을 수 있어 실제 정리는 모두 미지원으로 둔다. pytest 표식은 현재 파일명 구성만 확인하므로 내용 검증 전 후보임을 표시한다.

폴더 서명은 정렬한 메타데이터와 자식 서명의 SHA-256이다. 파일 내용의 동일성을 보장하는 해시가 아니며, 현재 단계의 변경 감지/검토용이다. 작업 전후 검사도 원자적인 경계 고정은 아니므로 휴지통 이동에 바로 사용하지 않는다.

후보 검토는 두 번 재탐색하고 포함 파일을 열거한다. 검토할 대상을 사용자가 직접 선택하며 작업을 취소할 수 있다. 향후 대규모 목록에는 모델 기반 가상화/한도 표시가 필요하다.

- Python 3.12 계열로 제한한다. 이 환경에서 발견한 3.12.14 x64 런타임을 사용한다. PySide6 6.10.2와 핵심/부가 모듈·shiboken6를 같은 버전으로 고정한다. 실제 설치 및 검증 결과는 PROGRESS에 기록한다. 최신 버전으로 무조건 올리지 않는다.
- Qt Widgets와 QThread를 사용한다. 취소는 threading.Event로 요청하고 파일/디렉터리 사이에서 확인한다. OS 파일 시스템 호출 자체를 강제로 끊지 않으며 작업 중 창 종료는 취소 요청 후 재시도하게 한다.
- os.scandir와 follow_symlinks=False 메타데이터만 읽는다. Python 재귀 호출 대신 스택으로 탐색하고 하위 폴더를 역순 합산한다. 폴더 행은 하위 포함 값이므로 행들을 다시 합산하면 안 된다.
- 링크와 Windows FILE_ATTRIBUTE_REPARSE_POINT(0x400)를 제외한다. 시작 경로의 모든 조상과 탐색 직전 디렉터리를 검사한다. 단, 메타데이터 검사와 OS 열기 사이의 외부 변경을 원자적으로 방지하는 핸들 기반 탐색은 아직 없다. 적대적인 동시 경로 교체에 대한 보장을 하지 않는다. 정리 기능을 추가하기 전에 별도의 검증이 필요하다.
- SQLite는 `%LOCALAPPDATA%\DevStorageManager\analysis.sqlite3`에 저장한다. 소스 폴더에 DB/로그를 쓰지 않는다. 프로젝트별 마지막 결과를 JSON으로 저장한다. 취소는 부분 결과로, 읽기 실패는 불완전으로, 재시작 시 running은 interrupted로 표시한다.
- 현재 폴더 수에 비례하여 메모리를 사용하고 파일 목록 전체는 보관하지 않는다. 결과 표는 폴더별 행을 일괄 구성한다. 대규모 폴더에서 UI 행 생성 병목은 아직 실측하지 않았다.
- 한국어 공통 문구·상태는 ui/strings.py에 분리했다. 나머지 UI/오류 문구 전체의 번역 카탈로그 전환은 후속 과제다.
- 삭제 API/Send2Trash는 아직 설치하거나 사용하지 않는다. 정리 보호 시험 이후 검증한 버전을 고정한다. 영구 삭제 fallback은 허용하지 않는다.
- Windows 배포는 pyside6-deploy를 우선 검토한다. 현재는 pythonw 소스 실행기를 제공한다. 실행 파일 빌드/서명/설치 및 깨끗한 환경 검증은 미완료다.
