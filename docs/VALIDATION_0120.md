전체 pytest **171 passed, 3 skipped** (`work/pytest-0120-verified`). 실제 링크 3종 생성 거부 skip은 통과로 계산하지 않는다. 개인 프로젝트는 시험 자료로 사용하지 않았다.

## 새 검사

- 한 부모 아래 두 번 생성해도 독립된 새 폴더이며 기존 파일 바이트가 보존된다. 실제 스캐너가 4파일과 Python 캐시 후보 1개를 찾고 기존 prepare가 내용 증거를 검증한다.
- 생성한 checked-hash pyc는 표준 Python 3.12 py_compile CHECKED_HASH 출력과 전체 바이트가 일치한다. 실행 시 예외를 발생시키는 자체 시험 소스도 생성/분석/증거 확인 중 실행되지 않는다.
- 원본/설정/.git 보호 표식이 rename 기반 휴지통 프로토콜 대역 뒤에도 보존된다. 이 대역을 실제 Windows 휴지통 성공으로 표현하지 않는다.
- 보호/.git/reparse 경계와 생성 전 취소는 하위 폴더를 만들기 전에 차단한다. 쓰기 오류/첫 파일 후 취소는 새 폴더의 부분 자료를 남기고 위치를 알리며 기존 파일을 삭제/덮어쓰지 않는다.
- 실제 Qt 흐름에서 폴더 선택 대역→작업 스레드 생성/등록/스캔/저장→후보 1행→검토를 연결했다. 자동 행 선택/정리 승인 없이 환경 미통과 상태는 실행을 차단한다.
- 실제 앱 폰트/스타일의 800×600 후보/도움말 화면을 확인했다(`work/demo-0120-800.png`, `work/help-0120-800.png`). 실제 후보 이름과 환경 확인 필요를 표시한다. 모든 모니터/DPI 검증은 아니다.
