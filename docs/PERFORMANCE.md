| 작업 | 완료(초) | 관측한 UI 최장 간격(초) | 반환 행 |

## 0.10.0 포함 파일 검토 50,000행

`scripts/benchmark_review_ui.py --rows 50000`, 결과 `work/review-benchmark-0100-final.txt`. 실제 앱 QSS/폰트를 적용한 Qt offscreen 검토 창과 검색 작업 스레드를 사용했다. 800×600 부모 안에서 776×568 창을 렌더링하고 실행은 비활성으로 유지했다.

- 표시·초기 정렬 완료: 0.179464초, Python 추적 최고 11,355,719 B. 이미 만든 합성 목록 생성은 제외한다.
- 초기 모델 data 호출 84회. 50,000개의 Qt 항목을 개별 생성하지 않고 보이는 행을 그린다.
- 1행으로 좁힌 검색: 200ms 입력 대기를 포함해 0.219291초.
- 그림: `work/review-benchmark-800.png`. 파일 행이 잘리지 않고 실행/닫기 버튼이 창 안에 보이는지 확인했다.

합성 경로/크기 메타데이터만 사용하며 실제 파일을 읽거나 이동하지 않는다. tracemalloc의 Python 할당만 포함하고 Qt native/전체 RSS/실제 후보 탐색·내용 검증은 제외한다. 모든 모니터/DPI의 시간이나 모든 캐시 검토 시간으로 일반화하지 않는다. 느린 작업 중 입력/취소/앱 닫기는 별도 이벤트/작업 대역으로 검사한다.

## 0.9.0 합성 이력 100,000건

명령: `.venv\Scripts\python.exe scripts\benchmark_history.py --rows 100000`. 원시 결과 `work/history-benchmark-090-comparison.txt`. 임시 SQLite에 100,000개 작업/항목 메타데이터만 만들었으며 실제 원래 경로를 읽거나 휴지통 작업을 하지 않았다. 읽기 전후 DB SHA256 일치와 임시 디렉터리 제거를 확인했다.

| 조회 | 반환 행 | 전체 일치 | 시간(초) | Python 추적 최고(B) |
|---|---:|---:|---:|---:|
| 첫 페이지 | 200 | 100,000 | 0.051667 | 167,970 |
| 먼 페이지 | 200 | 100,000 | 0.089537 | 151,116 |
| 경로 검색 | 1 | 1 | 1.410339 | 4,644 |
| 실패 이유 검색 | 200 | 10,000 | 0.659237 | 127,027 |
| 기존 전체 조회 API | 100,000 | 100,000 | 0.688754 | 61,546,968 |

전체 조회 대조는 0.8.1과 같은 SQLite API로 모든 행을 Python에 반환한 경우다. Qt 행 생성은 양쪽 모두 제외한다. tracemalloc 활성 상태의 단일 실행 측정이며 생성·해시·제거/SQLite native/Qt/전체 RSS는 포함하지 않는다. 경로/검색 분포와 디스크 캐시에 영향을 받으므로 다른 DB 성능을 보장하지 않는다. 전체 경로 검색은 모든 메타데이터를 검사하므로 페이지 조회보다 느리지만 작업 스레드에서 실행하며 표시용 행은 최대 200개다.

SQL count 시작을 확인한 뒤 취소 요청을 보내 0.017709초에 HistoryCancelled로 중단했다. 잠긴 OS 호출/물리적 디스크 고장 취소 시험은 아니다. UI 입력과 창 종료의 응답은 별도 QTimer/느린 조회 대역으로 검사했다.

## 0.7.0 큰 파일 목록 포함 재측정

직접 만든 128바이트 파일 20,000개, 루트 포함 101개 폴더, 논리적 2,560,000 B. 정상 완료/오류 0개를 확인했다. 추적 메모리 포함 분석 2.637188초, Python 추적 최고 1,600,745 B, 진행 17회. 취소 호출 0.004668초/cancelled. 파일 생성/제거, SQLite, Qt 및 전체 RSS는 포함하지 않는다. 상위 500개 정보가 추가되어 이전의 최소 메모리 결과와 기능 범위가 다르다. 실행마다 디스크 캐시와 부하의 영향을 받는다.

## 실제 파일 100,000개 추가 측정

`--folders 100 --files-per-folder 1000`, Python 3.12.14, 직접 만든 128바이트 임시 파일 100,000개와 루트 포함 101개 폴더. 관측된 논리적 크기는 12,800,000바이트로 입력 파일 수/크기와 일치했다. 생성/제거 시간은 아래 분석 시간에서 제외했다.

- tracemalloc 사용 상태의 분석 호출: **12.499초**.
- Python 추적 최고 할당: **1,296,989바이트**. Qt/전체 프로세스 메모리 또는 SQLite 저장 비용은 포함하지 않는다.
- 진행 이벤트 80회. 별도 취소 호출은 첫 진행 콜백에서 취소를 요청해 0.0064초에 cancelled로 반환했다. 멈춘 OS 호출 취소를 뜻하지 않는다.
- 측정 프로세스 종료 코드 0, 생성한 시험 폴더가 정상 제거된 것을 확인했다.

원시 출력: 작업용 `work/benchmark-100k.json`. 단일 반복이고 디스크 캐시/백그라운드 작업은 통제하지 않았다. 이 출력 형식에는 정상 분석 status/issue_count가 별도 기록되지 않았으므로 파일 수 일치를 넘어 오류 범위의 완전성을 증명하는 자료로 사용하지 않는다.

2026-10-30, 로컬 Windows Python 3.12.14 x64. `scripts/benchmark_scan.py`가 생성한 임시 파일만 측정. 디스크 캐시·백그라운드 작업을 통제하지 않았으며 정식 대용량 보증/벤치마크는 아니다.

입력: 100개 하위 폴더 × 200개 파일 = 20,000개 파일, 루트 포함 101개 폴더, 파일당 128바이트, 합계 논리적 2,560,000바이트. 생성/제거 시간은 분석 시간에서 제외. tracemalloc을 켜서 Python 할당 최고치를 관측하므로 프로세스 전체 메모리가 아니다.

| 구현 | 분석 시간 | Python 추적 최고 메모리 | 진행 이벤트 | 첫 진행 콜백에서 요청한 취소까지 총 호출 시간 |
|---|---:|---:|---:|---:|
| 모든 디렉터리의 파일 메타데이터를 종료까지 보관 | 2.354초 | 7,451,817 B | 13 | 0.0064초 |
| 현재 디렉터리만 보관하고 즉시 서명화 | 2.425초 | 967,119 B | 16 | 0.0052초 |

이 입력에서 추적 최고 메모리는 약 87% 감소했다. 단일 반복 결과의 시간 차이로 처리 속도 개선/악화를 단정하지 않는다. 캐시가 없는 디렉터리의 Python 원본명 집합도 즉시 버리도록 추가 개선했다.

제한: 폴더 수와 가장 넓은 디렉터리 항목 수에 비례한 메모리가 필요하다. 실제 큰 파일·하드링크·백만 파일·깊은 경로·네트워크·오류 다수·UI 결과 렌더링 측정은 남아 있다. 취소는 진행 콜백 기반 시험이며 멈춘 OS 호출을 끊는 성능을 뜻하지 않는다.

재실행: `.venv\Scripts\python.exe scripts\benchmark_scan.py`. 실제 사용자 폴더를 인자로 받지 않는다.

## 큰 결과 표

측정 보정: 이전 0.0073초 수치는 초기 활성 탭이 후보 탭인 상태의 모델 전달이었다. 폴더 탭을 실제 활성화한 오프스크린 재측정은 **0.0368초**, 입력 객체 생성 후 추가 Python 추적 최고 할당 **38,787바이트**였다. 100,000개 폴더를 모델에 전달하고 보이는 셀을 그리는 범위이며 전체 행을 한 번에 그린 시간이나 물리 디스플레이의 프레임 성능이 아니다.

`scripts/benchmark_ui.py`: 오프스크린 Qt 창에 100,000개 합성 폴더 행을 전달하고 이벤트를 처리한 단일 관측값은 약 0.0073초, 입력 행 객체를 미리 만든 뒤 추가로 관측한 Python 추적 최고 할당은 889바이트였다. 기존 행 객체의 메모리·Qt C++ 메모리·실제 디스플레이/스크롤 성능을 포함하지 않으므로 전체 메모리 사용량으로 해석하지 않는다. 첫 표시 때 전체 자동 정렬은 하지 않으며 헤더를 클릭하면 정렬한다.

추가로 3,000개 실제 임시 파일을 작업 스레드에서 읽는 동안 Qt 진행 신호 이후 검색 입력과 취소를 전달하는 통합 시험을 통과했다. 멈춘 네트워크/OS 호출의 취소 지연은 여전히 미측정이다.
