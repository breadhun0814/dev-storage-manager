# 사용자 검토 부담과 개발 묶음

사용자는 작은 수정마다 실행 파일을 보내고 재확인을 요청하는 방식이 부담스럽다고 명확히 지시했다. 개별 수정마다 중간 배포/시험 요청을 하지 않는다. 독립적으로 진행할 수 있는 구현·원본 보호 검사·UI 흐름·문서·배포 검사를 먼저 완료한다.

사용자 검토는 여러 기능이 연결된 의미 있는 묶음 단위로 준비한다. 실제 사용자 PC에서만 확인할 수 있는 항목은 검증 상태를 남기고, 작은 수정 확인을 반복 요청하지 않는다. 자동 작업이나 새 일정은 별도 요청 없이 만들지 않는다.

2026-10-31 사용자가 현재 버전을 GitHub에 올리고 사용 방법을 포함하도록 승인했다. 이전 업로드 보류는 이 요청으로 해제되었다. 현재 시험 버전의 소스·검사·설명서를 반영하며 완성/미검증 상태를 유지한다. 앱 DB/작업 로그/개인 파일/가상환경/생성된 빌드 폴더는 소스 저장소에 올리지 않는다.

0.7.0 묶음: 큰 파일 분석/검색/저장/CSV, 유형별 캐시 자격과 pytest 검증, 결과 불러오기 비동기화, 이전 DB 호환, Windows 하위 폴더 지문 보정, 취소 및 전체 검토·이력·재분석 흐름 검사.
