# 0.10.0 포함 파일 검토와 실행 범위

전체 pytest **154 passed, 3 skipped** (`work/pytest-0100-final`, 15.23초). 링크 3종 생성 거부 skip은 통과로 계산하지 않는다. 임시 시험 자료/합성 메타데이터만 사용했다.

## 새 검사

- 50,000개 확인 목록을 가상 표로 표시하고 원시 바이트 오름차순 정렬, 전체 경로/정확한 크기 선택, 리터럴 경로 검색과 0행 결과를 검사했다.
- 검색/행 선택 후에도 대상 전체 경로와 원래 50,000개 목록은 바뀌지 않는다. 처음 행을 선택하거나 실행 확인을 체크하지 않는다. 사용자 확인 이후에만 허용된 실행 버튼이 켜진다.
- 차단된 검토는 체크/실행 불가이며 불완전 목록/실행 조건과 구체적 제한을 설명한다.
- 표시 오류가 실행 확인을 해제하고 실행을 차단한다. 정상 재검색 후에도 체크를 자동 복원하지 않는다.
- 느린 인덱스 작업 중 QTimer 입력이 처리되고 스레드 ID가 UI와 다름을 검사했다. 검토 창 닫기와 부모 앱 닫기는 취소를 보내고 작업 종료 후 완료된다.
- 기존의 실제 임시 Python/pytest 검토→명시적 확인→rename 기반 프로토콜 대역→이력→재분석 흐름 및 원본/보호 검사도 통과했다. 이 대역을 실제 휴지통 이동 성공으로 표현하지 않는다.

## 화면과 측정

실제 스타일/폰트의 Qt offscreen 800×600 부모에서 776×568 검토 창을 확인했다. 상대 경로 표의 행, 전체 경로 확인 칸, 근거/주의/실행 조건 탭, 동의/실행/닫기를 분리했다. 창 밖으로 밀리지 않는 배치도 검사한다. 모든 DPI/실물 모니터를 시험했다는 뜻은 아니다.

50,000개 합성 목록의 창 표시+초기 정렬 0.179464초, Python 추적 최고 11,355,719 B, 초기 data 호출 84회. 검색은 200ms 입력 대기 포함 0.219291초. 메타데이터 생성/Qt native/RSS/실제 파일 탐색·내용 증거 검증/이동은 제외했다. PERFORMANCE.md와 `work/review-benchmark-0100-final.txt`에 기록했다.

## 실행물

소스 `work/startup-0100-source.json`과 Windows EXE `work/startup-0100-frozen.json` 자체 검사 모두 passed=true/버전 0.10.0을 확인했다. 실제 분석 complete/2파일/40 B, 큰 파일·폴더 항목 각 2행, 이력 1행/cancelled, 표시 전용 검토 2행/실행 비활성/미선택을 검사한다. 검토 표시 자료는 생성한 시험 파일의 메타데이터이며 정리 계획/실행 자격을 만들지 않는다. 실제 휴지통 이동은 하지 않는다. 패키징 도구도 이 검토 검사 필드를 필수로 확인한다.

## 미검증

검토 파일 50,000개 상한과 기존 정리 유형 자격을 늘리지 않았다. 새 pytest 유형의 정상 Windows 실제 이동/수동 복원, 깨끗한 별도 Windows 11, Windows 10, 서명, 모든 DPI, 실제 디스크 고장/모든 경합은 미검증이다. 사용자 보고와 에이전트 환경의 차단/skip을 구분하며 미검증 정리를 활성화하지 않는다. GitHub 업로드는 보류한다.
