## 새 검사

- 성공/실패/미확정/취소가 섞인 작업에서 성공 영수증으로 확인한 크기만 합산하고 전체 계획 크기/디스크 여유 공간과 구분한다. 상세 200개 제한이 전체 집계에 영향을 주지 않는다. 손상된 영수증/상태/크기를 성공으로 처리하지 않는다.
- 결과를 읽지 못하면 0 B나 성공을 표시하지 않고 원래 경로/오류를 보존한다. 작업 ID로 정확히 필터링하며 다른 검색/더 최신 작업이 방금 결과를 가리지 않는다. 전체 이력 복귀를 검사했다.
- 실제 임시 pytest 캐시의 검토→명시적 확인→rename 기반 대역→결과/이력→결과 창의 재분석 버튼→후보 소멸까지 연결했다. 개인 파일이나 실제 휴지통을 사용한 검사가 아니다.
- 스레드에서 실제 실패/이동 뒤 응답 유실/이동 뒤 계속되는 기록 실패를 주입했다. 추가 요청 없이 실패 또는 미확정/오류를 반환하고 원본 소스를 보존했다. 기록 실패를 제거한 재시작 복구도 검사했다.
- backend 호출 시 needs-analysis가 이미 DB에 커밋된 것을 확인했다. 앱을 새로 열어 이전 결과를 읽어도 후보/계획을 다시 사용하지 않으며 새 분석 후 후보가 다시 나온다. DB를 열지 못한 경우 backend 생성/요청이 없음을 확인했다.
- 여유 공간의 경계 검사 실패를 주입하면 disk_usage 호출 없이 미관측으로 남는다. 실제 전체 디스크 장애를 시험한 것은 아니다.
