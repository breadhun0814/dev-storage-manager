## 이력 저장/조회 검사

- 합성 메타데이터 451행을 200/200/51행으로 읽고 중간에 새 작업을 삽입해도 기존 페이지의 중복/누락이 없음을 확인했다. 새로고침하면 새 작업이 포함된다.
- 페이지 바깥/검색 바깥 성공도 해당 작업 전체의 이동 확인 크기에 포함한다. 실패 2건만 검색해도 작업의 성공 크기 합계를 0으로 바꾸지 않는다.
- 경로와 실패 이유의 전체 검색, Unicode casefold, `[100%_]`의 리터럴 검색, 마지막 페이지/빈 검색 결과를 확인했다.
- 읽기 전용 연결의 쓰기 거부, 조회 전후 DB 바이트 SHA256/mtime 불변을 확인했다. SQL count 중 취소가 실제 중단하고 같은 연결의 다음 읽기가 정상 동작하는지 검사했다.
- 정리 테이블이 모두 없는 초기 앱 DB만 빈 이력으로 표시한다. 일부 테이블 누락/데이터 형식 오류/SQL 오류는 실패이며 성공 또는 이력 없음으로 표시하지 않는다. 새로고침 재시도도 검사했다.
- QTimer로 느린 조회 중 화면 입력이 처리되는 것을 확인하고 실제 조회 스레드 ID가 UI와 다름을 검사했다. 닫기 요청은 취소 후 읽기 스레드/연결 종료를 기다린다.
- 조회 도중 검색어를 바꾸어 이전 결과가 최신 검색을 덮지 않고 최종 검색 1행만 표시되는 것을 확인했다.
- 저장된 running/pending 기록은 조회 시점의 완료 미확정/대기 기록이다. 이 기록만으로 현재 작업이 실제 실행 중이거나 성공했다고 표시하지 않으며 조회가 DB 상태를 바꾸지 않는 것을 검사했다. 기록 쓰기 실패 복구는 0.8.1 검사도 계속 포함한다.
