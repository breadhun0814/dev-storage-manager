## 이번 추가 검사

- SQLite 트리거로 running/성공/실패 기록에 쓰기 오류를 주입했다. running 선기록이 실패하면 백엔드 호출 0회다. 이동 후 기록 실패 또는 실패 결과 기록 실패가 나면 다음 항목을 실행하지 않는다. 확인할 수 없는 항목은 unknown, 미시작 항목은 cancelled로 남는다.
- 전체 완료 기록만 실패하면 확인된 개별 succeeded와 영수증을 보존하고 전체 작업은 interrupted다. 확인하지 못한 디스크 여유 공간은 None이다.
- 이동 후 중단 기록까지 계속 실패하는 경우도 추가 백엔드 호출 없이 오류를 전파한다. 주입 오류를 제거하고 다시 연 DB에서 running/pending이 unknown/cancelled로 회복되는 것을 검사했다.
- 복구 중간 SQL 오류가 모든 갱신을 롤백하는지 검사했다. 재시작 회복은 반복 호출해도 이미 확정/미확정 처리한 상태를 덮어쓰지 않는다.
- 누락된 대상, 실행 전 성공, 영수증 없는 성공, 항목과 불일치하는 전체 성공, 완료 상태 덮어쓰기를 거부한다.
- 검증 도중의 취소는 운영체제 요청 없이 cancelled다. 요청 후 캐시를 이동했으나 응답이 유실된 경우는 unknown으로 남고 이후 대상은 취소한다.
- Qt offscreen에서 전체 한국어/공백/긴 경로, 긴 실패 이유, 확인된 이동과 중단된 전체 작업의 별도 표시, 읽기 전용 상세 영역을 검사했다. 실제 모든 DPI 배율 검사를 의미하지 않는다.

파일 이동은 테스트가 만든 임시 폴더 사이의 rename 기반 프로토콜 대역이다. 이 검사를 Windows 휴지통의 실제 이동/복원 성공으로 표현하지 않는다. 개인 프로젝트를 읽거나 수정하지 않았다. 실제 디스크 고장/강제 전원 차단도 시험하지 않았다.
