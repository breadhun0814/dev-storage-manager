# 사용 방법 · 개발 저장공간 관리자 0.15.0

개발 프로젝트의 폴더 용량을 읽고, 근거가 있는 정리 후보를 검토한 뒤 사용자가 확인한 후보 폴더를 Windows 휴지통으로 이동하는 프로그램입니다. 시작할 때 정리는 비활성입니다. 현재는 시험 버전이며 [지원 범위](SUPPORT.md)와 [미검증 항목](RELEASE_AUDIT.md)을 함께 확인하세요.

## 1. 프로그램 실행

### Windows 실행 파일 ZIP을 별도로 받은 경우

1. ZIP 파일의 압축을 **모두** 풉니다. 압축 안에서 바로 실행하지 마세요.
2. 압축을 푼 `DevStorageManager-0.15.0-preview` 폴더를 파일 탐색기에서 엽니다.
3. 같은 폴더의 `_internal` 폴더를 그대로 두고 **DevStorageManager.exe**를 더블클릭합니다. EXE만 다른 위치로 옮기면 필요한 파일을 찾지 못할 수 있습니다.
4. VS Code가 열리면 `.py`/`.pyw` 소스 파일을 연 것인지 확인하세요. 파일 탐색기에서 확장자가 `.exe`인 파일을 실행해야 합니다.

### 이 GitHub 저장소의 소스로 실행하는 경우

GitHub **Code → Download ZIP**에는 소스 코드가 들어 있습니다. 위의 EXE는 포함되지 않습니다. Windows x64용 Python 3.12를 설치하고, 압축을 푼 저장소 폴더에서 PowerShell을 열어 다음 명령을 차례로 실행합니다. 관리자 권한과 PowerShell 실행 정책 변경은 필요하지 않습니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\pythonw.exe scripts\run.pyw
```

`py` 명령이 없다면 첫 줄의 `py -3.12` 대신 설치된 Python 3.12의 절대 경로를 사용합니다. 경로에 공백이 있으면 PowerShell에서 `& 'Python의 절대 경로\python.exe' -m venv .venv` 형식으로 실행합니다. 처음 의존성을 설치할 때는 인터넷이 필요하며 앱의 분석·정리는 로컬에서 동작합니다. 실행 파일을 직접 빌드하려면 [배포 안내](DEPLOYMENT.md)를 참고하세요.

## 2. 개인 파일 없이 먼저 익히기

1. 창 위쪽의 **관리 · 도구**를 누릅니다.
2. 메뉴에서 **시험 프로젝트 만들고 분석**을 누릅니다.
3. 새 시험 폴더를 만들 상위 위치를 선택합니다. 기존 개인 프로젝트를 선택할 필요는 없습니다. 앱이 `DevStorageManager-시험-…` 이름의 새 하위 폴더를 만듭니다.
4. 생성·등록·분석이 끝날 때까지 기다립니다. 이 작업은 실제 파일을 만들고 실제로 읽습니다.
5. 결과 영역의 **프로젝트·정리 후보** 탭을 확인합니다. 정상 완료된 시험 자료에는 `__pycache__` 후보 행이 나타납니다. 이 행은 파일 탐색기의 폴더 목록이 아니라 **앱 안의 정리 후보 표**에 있습니다.
6. 행을 한 번 클릭하고 아래의 **② 후보를 선택한 뒤 포함 파일 검토** 버튼을 누릅니다. 정리 버튼을 누르지 않고도 경로와 내용을 검토할 수 있습니다.

시험 폴더의 원본 `demo_owned.py`, `pyproject.toml`, `.git/KEEP.txt`는 정리 대상이 아닙니다. 시험 생성이 실패/취소되면 표시된 새 폴더 위치를 확인하세요. 앱은 남은 자료를 자동으로 영구 삭제하지 않습니다.

## 3. 실제 프로젝트 등록과 분석

1. **폴더 추가**를 누르고 분석할 개발 프로젝트 폴더를 선택합니다. 드라이브 전체나 시스템 폴더를 고르지 않습니다.
2. 창 위쪽의 프로젝트 선택기에서 방금 등록한 이름을 선택합니다. 전체 목록은 **관리 · 도구 → 프로젝트 목록 펼치기 / 접기**로 볼 수 있습니다.
3. **선택 프로젝트 분석**을 누릅니다. 오래 걸리면 **작업 취소**를 누를 수 있습니다. 읽은 부분의 결과와 취소 상태를 구분해 저장합니다.
4. **폴더별 용량** 탭에서 크기·파일 수·분석 범위를 확인합니다. 행을 선택하면 전체 경로를 확인할 수 있습니다. 작은 창에서 이름이 줄어 보이면 선택 경로/툴팁을 확인하세요.
5. **오류·제외 범위** 탭에서 읽지 못한 경로와 제외한 범위를 확인합니다. `—`는 0바이트가 아니라 전체를 확인하지 못했다는 뜻입니다.
6. **큰 파일** 탭은 읽은 범위의 상위 500개만 보여줍니다. 큰 파일이라는 이유만으로 정리 후보가 되지 않습니다.

용량은 KB/MB/GB/TB로 자동 표시하며 1 KB는 1,024 B입니다. 표시한 값은 **논리적 파일 크기**로 실제 디스크 사용량과 다를 수 있습니다. 폴더 크기는 하위를 포함하므로 부모와 자식 행을 더하면 중복됩니다. 화면 검색은 보기만 좁히며 분석 제외 설정이 아닙니다. 제외하려면 **관리 · 도구 → 분석 제외 목록**에서 프로젝트 내부 상대 경로를 입력하고 다시 분석합니다.

## 4. 후보 표가 비어 있다면

**프로젝트·정리 후보** 탭의 표에 행이 없으면 선택할 후보가 없는 상태입니다. 존재하지 않는 `__pycache__` 행을 찾거나 캐시를 직접 만들 필요가 없습니다.

- 프로젝트 분석을 실행했는지, 선택한 프로젝트가 맞는지 확인합니다.
- 취소/읽기 실패/제외가 있다면 **오류·제외 범위**와 상태 안내를 확인합니다.
- 분석이 완료되어도 근거가 있는 후보가 없을 수 있습니다. 분석 대상의 모든 파일을 삭제 후보로 만들지는 않습니다.
- 사용 흐름을 익히려면 빈 후보 화면의 **시험 자료로 사용 흐름 익히기** 또는 2절의 메뉴를 사용합니다.

## 5. 휴지통 이동 전 환경 확인

1. **관리 · 도구 → 정리 환경 확인**을 누릅니다. 앱이 직접 만든 시험 자료로 링크 경계·보호 경로·원본 보존·유형별 휴지통 동작을 확인합니다.
2. 결과에서 실패/미실행 항목과 상세 이유를 확인합니다. **관리 · 도구 → 환경 점검 결과 보기**로 다시 열 수 있습니다.
3. 공유 보호 검사와 **실행하려는 캐시 유형**의 휴지통 검사가 통과해야 합니다. Python 캐시의 통과가 pytest 캐시까지 승인하지는 않습니다.

점검은 관리자 권한이나 보안 설정 해제를 요구하는 절차가 아닙니다. 실패하면 원인을 확인하고 정리를 실행하지 않습니다. 앱을 다시 열면 실행 자격은 초기화됩니다. 이전 점검 기록이 남아 있어도 이번 실행의 승인이 되지는 않습니다. 환경 확인이 만든 시험 캐시는 휴지통에 남을 수 있습니다.

## 6. 후보 검토와 휴지통 이동

1. **프로젝트·정리 후보** 탭에서 정리할 **후보 행 하나**를 클릭합니다.
2. **② 후보를 선택한 뒤 포함 파일 검토**를 누르고 검토가 끝날 때까지 기다립니다.
3. 새 검토 창의 위쪽에서 **정확한 대상 폴더**와 크기를 확인합니다. **포함 파일** 탭에서 검색/정렬하고 행을 선택해 전체 경로를 확인할 수 있습니다.
4. **근거·주의·실행 조건** 탭에서 분류 근거, 재생성 조건, 제한 이유를 읽습니다. 가상환경·node_modules·빌드 폴더는 현재 검토 전용입니다.
5. 내용 검증과 환경 조건을 충족한 경우 **대상 폴더 전체와 재생성 조건을 확인했습니다.** 체크를 직접 선택합니다. 처음에는 선택되어 있지 않습니다.
6. **③ 확인한 후보 폴더 1개를 휴지통으로 이동**을 누릅니다. 실행 직전 변경 여부를 다시 검증합니다. 변경되었다는 안내가 나오면 다시 분석하고 검토합니다.

**포함 파일의 행 선택/검색은 개별 파일 삭제 선택이 아닙니다. 이동 대상은 검토 창 위에 표시된 후보 폴더 전체입니다.** 체크나 실행 버튼이 비활성이면 제한 이유를 확인하세요. 환경 실패, 내용 변경, 링크/추가 파일, 지원하지 않는 캐시 형식 등을 우회 활성화하지 않습니다. 재설치·재빌드 명령은 안내만 하며 자동 실행하지 않습니다.

## 7. 결과와 이력 확인

작업 후 **정리 실행 결과** 창에서 성공·실패·취소·미확정을 구분합니다. **이 작업 이력 보기**로 해당 실행만 확인하거나 **정리 이력** 탭에서 원래 경로/실패 이유를 검색할 수 있습니다.

- **휴지통으로 이동 확인된 크기**와 **관측한 디스크 여유 공간**은 별도 값입니다. 휴지통으로 이동했다고 바로 여유 공간이 늘지는 않습니다.
- 실패/미확정이면 원래 경로와 Windows 휴지통을 확인합니다. 앱은 영구 삭제로 전환하거나 성공으로 추정하지 않습니다.
- **프로젝트 다시 분석**으로 최신 상태를 확인합니다. 정리 시도 뒤에는 재분석 전까지 이전 후보를 다시 실행할 수 없습니다.
- **목록에서 제거**는 등록 기록을 없애는 기능이며 실제 프로젝트 폴더를 삭제하지 않습니다.

## 8. Windows 휴지통에서 수동 복원

1. 앱의 **정리 이력**에서 원래 경로와 실행 시간을 확인합니다.
2. Windows 바탕 화면의 **휴지통**을 엽니다.
3. 이름뿐 아니라 원래 위치와 삭제 시각이 일치하는 항목을 찾습니다. 같은 이름의 `__pycache__`가 여러 개일 수 있습니다.
4. 해당 항목을 마우스 오른쪽 버튼으로 누르고 **복원**을 선택합니다. 원래 위치에 같은 이름이 있으면 Windows 안내를 확인하고 임의로 덮어쓰지 않습니다.
5. 원래 경로의 내용이 돌아왔는지 확인하고 앱에서 프로젝트를 다시 분석합니다.

앱은 자동 복원과 휴지통 비우기를 제공하지 않습니다. 휴지통에서 이미 영구 삭제한 항목을 이 앱으로 복구할 수는 없습니다. 현재 버전의 실제 수동 복원과 깨끗한 Windows 설치 검증은 아직 완료되지 않았습니다.

## 9. 기록 위치와 도움말

앱 설정·분석 DB·정리 이력은 `%LOCALAPPDATA%\DevStorageManager`에 저장합니다. 프로젝트 소스에 일반 실행용 DB를 만들지 않습니다. **관리 · 도구 → 사용 방법**에서 앱 안의 안내도 읽을 수 있습니다. 보고서에는 프로젝트 경로가 포함되므로 공유 전 내용을 확인하세요.
